Worldkeeper v0.2.0 makes what shipped in v0.1.0 dependable, and lets you rename and delete worlds.

> **Status:** a personal project, shared as-is. I use it myself. There are no guarantees on support or response time.

## Highlights

- **Rename and delete worlds.** Renaming changes the name shown in the game. The folder keeps its name, so the world stays linked to its saves. Before deleting a world, Worldkeeper saves it unless its latest state is already saved, so you can load a deleted world back.
- **Progress for big backups and restores.** Saves and restores run in the background with a progress bar, so a large world no longer leaves the page waiting on "Saving…". You can leave the page while one runs. Automatic backups show up there too.
- **"Load as a new world" gives the copy its own name**, "… (restored <date>)", so the game no longer lists two worlds with the same name.
- **The Activity feed survives restarts.** The last 100 events are kept in `events.json` next to the config, so a failure from before a restart stays visible.
- **Your NAS can sleep.** The tray status no longer reads the backup storage every 15 seconds. It reads it once and then keeps track of new backups, so network disks can spin down between games.
- **Opening a world is never blocked.** On Windows, the check for whether a world is open no longer takes a lock on `session.lock`, so it can never stop the game from opening a world. Detection is now tested against Java's own file locking.
- **No console window flashes on Windows** when Worldkeeper runs restic.
- **The running version** is shown in the web UI footer, with a link to its release notes, and in the tray menu.
- **World info checked on real saves from 1.16.5, 1.20.6, 1.21.11 and 26.3.** In v0.1.0 only 26.x had been checked.

## Install

Download the archive for your system, unpack it, and run `worldkeeper`. The web UI opens at `http://127.0.0.1:25599` on the first start. To upgrade from v0.1.0, quit Worldkeeper from the tray and replace the program. Your settings and saves stay where they are.

| System | Archive |
|---|---|
| Windows (most PCs) | `windows_amd64.zip` |
| Windows on ARM | `windows_arm64.zip` |
| macOS, Apple Silicon (M1–M4) | `darwin_arm64.tar.gz` |
| macOS, Intel | `darwin_amd64.tar.gz` |
| Linux | `linux_amd64.tar.gz` / `linux_arm64.tar.gz` |

**The binaries are not signed:**
- **Windows:** SmartScreen will warn on the first run. Click *More info → Run anyway*.
- **macOS:** clear the quarantine flag first: `xattr -d com.apple.quarantine ./worldkeeper`.

To start Worldkeeper with your computer, see the README.

## Known limitations

- Java Edition only.
- The tray and menu bar icon have been run by hand on Windows. On macOS and Linux they have been checked by building only.
